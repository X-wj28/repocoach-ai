# RepoCoach Agent 升级变化与成效

这次升级保留Next.js、NestJS、PostgreSQL、Prisma和DeepSeek，将仓库面试问答升级为有代码依据、可恢复、可观察的领域Agent应用。产品功能和工程验收已完成；发布结果将在Render验收后补充。

## 升级前后

| 方面 | 原来的行为与问题 | 新版行为 | 已验证的效果 |
| --- | --- | --- | --- |
| 问题来源 | 后续题可能使用预置的其他项目路径 | 四道候选题绑定实际文件、代码片段与行号；快照固定commit/blob | 非法路径不落库，恢复后仍使用原项目上下文 |
| 代码取证 | 依赖初始提供的文件 | search_code、read_file、get_file_outline受限工具循环 | 覆盖额外读文件、越权、空命中、工具错误及预算耗尽 |
| 回答提交 | 超时重试或竞争提交可能跳题；先推进再保存 | questionId绑定题目，回答先持久化；完成评价与题号同事务 | 同题同回答复用原结果；不同回答409；写入失败整体回滚 |
| 失败恢复 | 模型或数据库错误容易进入不准确的兜底流程 | 取证和评分独立checkpoint；租约限制竞争；每阶段最多3次尝试 | 重建应用后恢复原答案；评分重试的取证次数和证据保持不变 |
| 评分解释 | 单一总分，规则反馈混入能力结论 | 四项Rubric、证据ID校验、服务端加权；无法判断时总分为空 | 可复盘每项理由；无分和演示结果不进入能力均分 |
| 执行过程 | 请求处理中缺少可回放的步骤 | 持久化事件、连续序号、SSE及Last-Event-ID补发 | 并发事件序号连续；状态与事件同事务；浏览器真实断线后重连 |
| 后续练习 | 训练之间缺少可追溯的练习重点 | 最多40条有据观察，新训练最多优先两个薄弱维度 | 可回到原题；用户/项目隔离；清除epoch阻止旧任务晚到写回 |
| 完成与网络边界 | 完成后当前训练空200响应；收到响应头就取消超时 | 明确JSON null；超时覆盖完整响应体 | 四题完成后可正常查询；正常/错误响应体卡住均能超时 |
| 交付 | 本机失效代理阻塞Git/Docker，缺少完整HTTP回归 | 修复Docker代理；Web避免无关引擎下载；发布分支CI与版本标记 | 本地前后端容器、数据库迁移、原会话及SSE恢复均已通过 |

## 面试能展示的工程能力

该项目提供一条可以现场演示并用源码解释的链路：固定代码版本 → 受限取证 → 保存证据 → 引用校验评分 → 原子提交 → SSE复盘 → 后续练习。评分失败后的恢复和清除记忆的竞争边界都有可重复的自动化场景，不依赖现场网络刚好成功。

与已有的终端Coding Agent形成互补：终端项目侧重通用执行环境、Shell/MCP权限和会话恢复；RepoCoach侧重领域取证、评价契约、用户隔离、事件回放和自适应练习。新版没有引入LangGraph/DeepAgents，也没有实现多Agent或逐工具结果checkpoint。
