## 复现命令

需要 Node.js 22、项目依赖、Prisma Client；数据库测试需显式设置专用 `TEST_DATABASE_URL`。浏览器测试需要已有 Chrome/Edge，可通过 `BROWSER_EXECUTABLE` 指定路径，不会自动下载浏览器。

```powershell
npm ci
npm run db:generate
npm run test:api
npm run test:web
# 使用专用测试数据库，两个命令各自创建并删除随机 schema。
$env:TEST_DATABASE_URL = 'postgresql://repocoach:repocoach@127.0.0.1:5432/repocoach?schema=public'
npm run test:integration
npm run test:e2e
npm run eval:rubric
npm run lint
npm run build
npm run test:browser
```

涉及 API 构建的命令按顺序执行，避免同时改写 `dist`。浏览器测试启动自己的前端与固定 API，均使用随机本机端口，不需要先运行 `npm run dev`；退出时关闭本次启动的进程。截图与 JSON 检查结果写入 Git 忽略的 `data/browser-acceptance-<uuid>/`。

## 实际成效与讲解重点

这轮将原本集中展示题目与反馈的页面，升级为“观察执行 → 核对源码 → 逐题复盘 → 选择下一次练习”的完整工作区。草稿刷新丢失、恢复错误被忽略、旧请求覆盖新项目、最新训练完成后恢复旧训练等边界，都有对应修复与回归。可见性、恢复路径和可复现验证是本轮的成效，没有据此声称面试分数或真实学习效果提高。

面试时可以围绕三个实现问题展开：为什么阶段条读取持久化状态；为什么服务端回答与本机草稿要区分；为什么请求返回前必须再次确认账号、项目和操作仍然有效。状态入口位于 `apps/web/lib/use-training-session.ts`，草稿规则位于 `drafts.ts`，浏览器验收入口位于 `apps/web/test/browser/acceptance.cjs`。

八分钟演示步骤见[演示手册](demo-guide.md)，界面交互和数据边界见[可视化工作台](visual-workbench.md)。人工评分校准、多租户生产吞吐、私有仓库和语音面试留在后续范围。
