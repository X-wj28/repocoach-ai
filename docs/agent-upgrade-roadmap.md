# RepoCoach Agent 升级路线

## 定位与已有知识

升级目标：保留 Next.js + NestJS + PostgreSQL，把 RepoCoach 做成基于代码证据的自适应项目面试 Agent，作为 Agent 应用工程求职作品。

根据开发者提供的另一个项目经历，已有实践涉及 AgentHarness 组装、Tool Calling、权限与审批、Checkpoint/SQLite、上下文管理和任务验收。这里把这些经历视为实现背景，不把学习目录的覆盖面当作每项能力已经熟练的证明。

参考的学习材料包括 [Runtime 学习路线](https://github.com/Link-990/Agent-learning/blob/main/03-Agent-Runtime/README.md)、[Checkpoint 与 Durable Execution](https://github.com/Link-990/Agent-learning/blob/main/03-Agent-Runtime/08-durable-execution.md)、[RAG 学习入口](https://github.com/Link-990/Agent-learning/blob/main/04-RAG%E4%B8%8E%E7%9F%A5%E8%AF%86%E5%BA%93/README.md)和[企业级工程化入口](https://github.com/Link-990/Agent-learning/blob/main/07-%E4%BC%81%E4%B8%9A%E7%BA%A7%E5%B7%A5%E7%A8%8B%E5%8C%96/README.md)。采用其中对状态、恢复边界和评测的要求，按产品需要逐步实现。

两个项目可以形成互补：终端 Coding Agent 展示通用执行环境和工具权限；RepoCoach 展示领域内的代码取证、评价质量、用户状态与可观测性。当前不需要为了引入 LangGraph 再维护一套 Python 服务。

## 代码审查发现

原实现已经包含公开仓库读取、账号隔离、DeepSeek 调用、Prisma 持久化、报告和部署配置。主要缺口如下：

| 问题 | 影响 |
| --- | --- |
| 首题之后预置其他项目的购物车、商品列表文件路径 | 问题无法回到用户的代码验证 |
| 恢复题目但不恢复项目上下文 | API 重启后即使模型可用也会进入规则评分 |
| 先更新题号，再保存答案，且数据库错误位于模型降级捕获范围内 | 写入失败可能跳题或重复推进 |
| 提交不带题目 ID | 超时重试和多标签页可能将旧回答提交给新题 |
| 模型未返回下一题时提前结束 | 一次结构化输出缺失会缩短训练 |
| 规则关键词分与模型分一起计算能力报告 | 演示规则会影响用户能力结论 |
| 前端在真实提交失败后生成本地成功反馈 | 用户无法判断回答是否保存 |

## 第一阶段：证据与恢复（本次实现）

- 四道候选题全部从实际读取到的文件规划，绑定服务端提取的代码片段与行号。首题不等待模型。
- 训练创建时保存独立的项目上下文。恢复后优先使用这份上下文；旧会话没有快照时兼容读取项目快照。
- 评分上下文优先放入当前和候选题文件，最多四个文件，每个最多 6000 字符；另附当前题目的证据片段。
- 模型生成的追问必须引用当前提供的文件，代码片段由服务端生成。无效路径或缺失追问使用候选题继续训练。
- 提交携带 `questionId`。已提交的相同回答直接返回保存的评价；同题不同回答、过期题目与完成会话返回冲突。
- 用 `currentQuestion` 和状态作为条件更新，在同一 Prisma 事务中推进题号、保存答案与完整评价。写入失败整体回滚。
- 真实会话提交失败时保留输入并提示重试。演示反馈保留在历史中，能力平均分仅采用非空模型总分；第三阶段将配置模型后的故障改为持久化失败状态。
- 模型请求的超时覆盖响应头和响应体读取。

验收场景：服务重启后仍使用原上下文；已提交响应丢失后重试不再评分；保存答案失败不跳题；并发提交只保存一次；不存在的模型路径不落库；仅有演示分时没有能力分。

第一阶段当时的边界：并发请求可能各自调用模型，只有数据库提交被去重，还没有worker或lease。第三阶段已加入阶段checkpoint与租约。文件路径存在仍不证明问题语义正确，Prompt也不证明完全消除注入；模型返回后、checkpoint前崩溃仍可能重复调用。

## 第二阶段：只读代码检索与 Tool Calling（已实现）

新增 `search_code`、`read_file`、`get_file_outline` 三个只读工具，让模型根据问题请求证据。路径搜索覆盖可读清单，正文搜索仅覆盖已加载文件前缀；结果明确展示搜索范围与索引是否截断，空命中不代表整个仓库不存在相关代码。文件结构是词法提取，未宣称 AST。

在 NestJS 中实现 `Model -> Tool -> Observation` 循环。新仓库分析先固定 commit，再读取其 tree SHA；额外读取使用保存清单中的 blob SHA，不能使用模型提供的 URL。排除环境变量文件、密钥、部分常见秘密文件名、依赖和产物、符号链接以及超过 256 KiB 的文件；这只是读取策略，不是内容级秘密检测。

取证预算：最多 4 次模型请求、6 次工具执行、2 次新文件读取、45 秒总时限；清单最多 3000 个文件，每个保存最多 12000 字符，单个工具结果最多 5000 字符、结果累计最多 20000 字符。GitHub 请求单次最多 10 秒；最后一轮禁用工具，即使模型继续请求也不执行。记录版本、工具名、参数摘要、状态、耗时和 Token；工具失败作为观察结果提供给模型。第三阶段另加一次最多25秒的评分调用，故障进入阶段失败而非规则评分。

检索记录、新增代码上下文、评价和题号在同一数据库事务保存。答案重试返回原检索记录；前端在反馈和历史复盘中提供“查看分析依据”。旧快照没有 commit/清单时只支持已保存文件，需要重新分析才启用远程读取。

已验证：问题需要的文件不在初始集合时能定位；非法工具、越权路径、空命中和预算耗尽可解释；网络故障形成明确观察结果；固定版本和检索记录可恢复。真实项目上的证据命中率比较尚未完成，因此不宣称检索质量提高了某个百分比。

## 第三阶段：Rubric 与阶段恢复（已实现）

将一个总分拆成正确性、代码依据、技术取舍、失败边界四项。评分理由引用服务端证据 ID；任一维度无法判断时总分为空，分项理由仍能复盘。追问从已保存证据中选择实际文件。模型评价仍是估计，不是客观能力认证。

已提供 20 条固定合成样例，包含优秀、含糊、事实错误、注入和上下文不足的回答。评测脚本记录初始预期符合数、排序比较、结构/引用有效率、延迟、Token 和版本；默认只校验样例，显式 live 命令才调用模型。人工复核数量仍为 0，尚未形成独立质量基准。

提交先持久化回答与任务，取证成功后保存 checkpoint，再执行独立无工具评分。评分故障不推进题号；重试只执行评分阶段，已有回答和证据不变。worker 使用租约和条件更新恢复进程中断，每阶段最多三次尝试，最终完成与题号推进原子提交。空队列停止查询。

验收：20 条样例的 v2 格式与引用校验通过，12 组排序符合初始预期，4 条证据不足样例有效返回无法判断；同一数据集用于调试与验证，不宣称线上准确率。真实四题 HTTP 流程、浏览器刷新恢复与按钮重试已通过。详见 [评分与恢复说明](rubric-and-recovery.md)。

## 第四阶段：执行事件、SSE 与训练记忆（已实现）

区分Interview、EvaluationRun和EvaluationEvent；任务、模型与工具步骤、证据checkpoint、重试和评分结果保存为按run连续排序的事件。对应阶段事件与业务状态同事务落库。SSE按Last-Event-ID补发，前端去重，连接故障用状态查询兜底；复盘加载持久化事件。

新增TrainingMemory，仅从有效、非空、有引用的模型分项保存观察，每用户/项目最多40条。最新低分确定练习重点，高分更新同维度的练习历史；新训练最多优先安排两个维度并调整难度。记忆查询按用户隔离，清除递增epoch，清除前任务不能晚到写回；原始复盘与当前题目保留。

已验收真实模型23条事件的主动断开/补发、浏览器实际连接切断后的Last-Event-ID自动重连、来源复盘、手机布局与记忆清除。真实数据库验证连续序号、分页、完成回滚及清除屏障；详见[事件与记忆说明](events-and-memory.md)。步骤事件用于观测，并非逐工具结果checkpoint。

## 第五阶段：可视化工作区与演示稳定性（本地完成）

将五阶段执行进度、工具事件、源码依据和四项反馈连接到宽回答区；历史逐题复盘与交互式报告形成从评分回到来源题、再开始训练的闭环。补齐本机草稿、恢复失败重试、启动/提交失败保留，以及切换项目后忽略迟到响应。最新训练完成后不会恢复更早遗留的未完成训练。

2026-10-28 完成本地求职演示版验收，尚未部署。已有 Chromium 生产界面验收脚本并接入 CI 配置，实际结果与范围见[本地验收](demo-readiness.md)，截图及交互见[可视化工作台](visual-workbench.md)。

同日继续补齐[本次训练小结](session-summary.md)，将完成训练、逐题结果、可引用的低分建议、依据缺口和下一次训练连接起来。它复用持久化详情与既有训练记忆，不增加模型调用；小结加载失败、历史回看和开始新训练的边界纳入本地浏览器回归。

整体验收收尾已提供八个完整NestJS HTTP场景和四项前端请求边界测试，并接入CI。包括重建应用后恢复评分失败、保持证据不变的阶段重试、四题结束后的空状态、SSE补发及记忆清除。现场操作步骤见[演示与验收手册](demo-guide.md)。

本次可演示：导入真实项目、展开代码依据、提交回答、查看取证/评分阶段、四项评分理由与源码引用、刷新恢复、仅重试评分、重复提交返回原评价。故障测试展示原子提交、租约隔离与权限隔离。

可以表述为“实现受限Tool Calling、固定代码版本、Rubric引用校验、阶段恢复、SSE事件回放、可追溯训练记忆及合成评测”。多Agent、逐工具恢复、人工校准准确率和生产吞吐指标仍未实现。测试通过与模型质量提升需要分别记录。

## 本地使用与发布

新增独立上下文、评价JSONB、版本/清单、evaluation_runs、evaluation_events及training_memories，总分允许为空。新前端携带questionId并订阅202任务，前后端必须配套更新；旧已提交评价保留原格式，升级前任务仅补状态快照事件。

```powershell
npm run db:generate
npm run db:deploy
npm run test:api
npm run lint
npm run build
```

`db:deploy` 会修改 `DATABASE_URL` 指向的数据库，应在准备运行新版的目标环境执行。真实模型请求需要 DeepSeek 配置；自动化单元测试使用模型和数据库替身，不会调用计费模型。

2026-10-14发布验证：68项API测试、4项前端HTTP测试、10个PostgreSQL场景和8个完整HTTP场景通过；真实PostgreSQL在独立临时schema中执行8个迁移，包括事件连续序号、分页补发和清除记忆后的旧任务隔离。GitHub Linux CI全部通过。

真实 DeepSeek 与公开 GitHub 仓库的新版四题 HTTP 流程已通过，桌面和手机复盘界面已检查，刷新后失败任务恢复和真实评分按钮重试也已验证。这些是功能验收结果，不能代替人工标注集的评分质量评测，详见 [验收记录](agent-acceptance.md)。

Render免费数据库到期后已完成Neon空库恢复，见[迁移说明](neon-recovery.md)。2026-10-14已应用全部迁移并配套更新Render前后端；真实线上四题、SSE补发、浏览器复盘与记忆清除通过。版本和实际成效见[发布总结](release-summary.md)。
